# 有界单次预测修复计划

2026-11-22，基于 V4.0 `b2dc1ca`。本轮只修现有预测执行线，不扩题型、渠道平台或视觉功能。

## 本次问题与目标

用户真实题“英伟达股票走势”消耗 628073/1000000 tokens，39/40 模型请求后未发布。两个有效报告都来自统计席；市场与核验席碰到个人 65536 上限。focus 失败、报告修正、主 Agent 重复汇总和发布闸门／补查规则脱节导致额外费用。交易市场在实体识别前按 HK 默认冻结，也存在口径冲突。

本轮目标：单次研究默认不开监听；主 Agent 短规划与最终裁决；研究员各取有限材料并提交概率、依据和缺口；预算先留报告及收尾；能在真实来源下正常发布有依据的结果。资料不足仍交付可读阶段性答复，不填造概率或把未完成核验称为成功。

## 实施范围与分工

1. 前端：只加“持续关注”默认关闭选项，提交显式 watch；研究目的不监听，复制任务保留选项。后端公开 watchEnabled 区分布尔选择与计划对象。已有题目／监听保持原记录，不静默改变。
2. 来源工具：保持已接通的搜索／网页服务，借鉴成熟项目的正文质量与缓存设计。Run 内按 URL 缓存正文，focus 未命中明确降级为真实片段和提示；不将浏览器错误／登录壳当证据；不向 NVDA 暴露 BTC/ETH 专属行情能力。每个读者仍分别记录实际读取，跨 Run 隔离。
3. Worker：预算前检包含输入、工具 schema、输出与报告保留；低余量提前只报告，并留修正机会。依据真实工具结果压缩上下文，保持协议配对、引用、权限和真实用量。普通预测不再自动灌入全套财报研读方法。
4. 主 Agent：新执行策略主要做简短题意重写／选方向、最终读报告与每席概率进行裁决。通用规范化优先由程序根据草稿、实际证据及固定规则完成；保留严格契约。每阶段仅有限纠错，最多一次有目标的补查；不用无效补查反复冲击发布条件。
5. 交付：按不同角色的有效替代报告认定独立性，不能同席两份算两席；固定价格三席守卫继续保留。汇总超限时可用已验证报告做确定性汇集；有足够独立依据及候选概率才封存明确标注的聚合估计，否则返回已知／未知／失败原因的阶段性结果。
6. 市场与时间：新交易日题在冻结前识别明确的标的／上市市场；不把未来结果作为当前报告的必需材料，不改写已封存历史。

## 新策略与兼容

新预测使用独立的预算策略标记；旧任务保留原预算、契约、来源、用量和失败。参考聚合采用不同角色的有效候选概率，证据充分度／来源独立性单列，不宣称统计校准或准确率提升。角色分数用于汇总解释，不把来源数量机械转换为事件概率。

## 检索资源取舍

候选以官方仓库为依据：Mozilla Readability、Trafilatura、Jina Reader。当前主故障发生在已拿到正文后的定位及引用修正，先修网关与缓存，不默认再引入需要不同运行时、DOM 或新的外部转发服务。记录实际采用部分，不把参考项目写成已安装依赖。

## 验收顺序

1. 定向离线回归：监听默认关闭／显式开启、输入＋输出预算、报告余量、同页 focus 降级、错误资产工具隔离、补查替代与同席去重、严格价格守卫、取消与归属。
2. 全套回归使用受控并发，避免已知本机 HTTP 测试高并发超时。代码回归不代表真实模型预测成绩。
3. 启动独立验证实例，原 4174 用户服务不在修改过程中重启或回写。通过当前用户授权的会话凭据进行限定预算的新真实验证；不把 Key 写入源代码、日志、命令行或证据。
4. 验证以原问法“英伟达股票走势”为优先，记录三席是否完成、工具／主 Agent 次数、实际 tokens、来源与引用、正常发布及 watch=false。失败保留，不改写成成功；若真实服务条件阻碍，说明确切原因。
5. 成功后提供真实结果与前后差异，更新本文件、实现状态及 PRD 决策记录。未获本轮上传指令不推送 GitHub。
