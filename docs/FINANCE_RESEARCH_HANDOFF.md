# 财报解读与双语新闻核验交接

2026-11-21；继续仅本地开发，未上传 GitHub。用户已明确选择财报解读及管理层表述核验，股价预测不在本批范围。

## 已实现

- 新建任务选择「财报解读与表述核验」；API 使用 `purpose: research`。独立取证、必要补查后封存公开研报，不创建未来二元契约、不给概率、不计分且不自动监听。
- 官方、统计、新闻时间线、行业、人物及核验按金融问题加载 `finance-methods-v1` 方法快照；角色设置页可查看财报专项方法。旧自定义角色和检查点不静默改写。
- 时间线与核验的 `search_news` 真实执行中文/英文两路搜索，保留渠道失败、合并追踪参数不同的同一链接。搜索结果始终不是已读证据。允许中外公开站点，不绕过登录或付费限制。
- `fetch_page` 可用 `focus` 定位财报表格；保存片段位置、截断和语言提示。语言提示为启发式，不代表来源独立性。
- 统计席的 `compare_financial_metrics` 对本人已读原文中的数字作确定性货币单位换算与增长率计算；校验单位、币种、会计口径及同比/环比期间，不能直接推断股价或因果。
- 研报与预测分表、事务封存；来源时间、引用、逐报告裁决、跨运行隔离及重复发布由后端守卫。任务页与协作摘要支持研报展示及公开 JSON 导出。
- 研报取证和最终整理使用低思考强度，取证快照为 `finance-efficient-v1`。预留收尾报告 token；预算耗尽可生成明确标识的资料缺口回执，不伪造研究员结论。并发请求预留输入及输出预算，用量未知时停止继续付费请求。

第二次取证完成三席并取得6条中英文正文记录；初次汇总及首次续写均在8192输出上限截断，累计112860 tokens。这个上限是项目应用的配置，不是课程要求或Codex强制限制。用户随后明确授权再重试一次，汇总额度提高至16384；总预算和原Run保持不变，取证不重跑。较长上下文先被预算预检无费用拦截，之后汇总输入从27162字节缩至10252字节，最终新增一次模型请求成功，累计122609 tokens、14模型请求、13工具调用。主Agent真实研报已封存，原失败事件全部保留。案例页含2个模拟财报案例和2条真实存档。

人工复核发现原始研报中FY2028展望的引用没有完整支持整条主张，旧GTC引语也缺一手核验。真实存档与案例页保留这些复核备注；不把“执行成功”冒称“内容全部正确”。核对版财报与详细调试结论见[最终报告](FINANCE_RESEARCH_REPORT.md)。下一步优先补逐条子主张与原文片段的对应验证。

`POST /api/v1/course/runs/:runId/resume-summary` 仅已完成有效报告、用量已知且仍有原预算的研究任务可用。同一Run最多两次手动续写，每次只允许一个额外模型请求；只开放提交研报或明确不足，禁止重跑工具或补查。恢复事件记录次数、输出额度及`research-summary-v2`策略，原失败事件保留。`POST /api/v1/course/runs/:runId/assemble-report` 可在汇总截断后，无模型或联网调用整理已有报告。整理版保存`assemblyMode:harness`、`quality:limited`及原失败，页面明确主Agent最终裁决未完成；不会冒充模型成功研报。

预检若发生在模型调用计数预留前，允许通过主Agent调用次数与全部完成Worker的计量核对一次未发请求；只有确认差额为1、用量已知且未用过此恢复才可重试，不增加付费续写次数。真实本轮验证了该路径。任何用量未知或已发模型请求均不能冒充零费用恢复。

自动结算、预测准确率评估、全市场股票行情及完整因果识别仍是独立后续工作。本批工具验证、研报解释和来源核验不作为投资收益或预测准确率成绩。
