## 分工与监工方式

| 开发角色 | 负责内容 | 首批文件边界 | 交付证据 |
| --- | --- | --- | --- |
| 主 Agent | 契约、依赖、集成、进度及最终验收 | 运行服务、HTTP 接线、计划与状态表 | 完整路径测试、问题清单、验收结论 |
| 后端 Sub-Agent | SQLite、事务事件、检查点、工具回执及取消 | server/core/store.mjs 与测试 | 临时库重开、独立进程恢复、事务回滚 |
| 模型 Sub-Agent | DeepSeek 原生工具协议、Worker 循环及预算 | server/runtime/model-provider.mjs、worker-loop.mjs 与测试 | 真工具处理器、协议消息配对、权限/失败/取消 |
| 前端 Sub-Agent | 新事件投影器、人物状态和后续页面接入顺序 | web/run-projection.mjs 与测试、前端交付说明 | 多运行隔离、去重、重连、终态不倒退 |
| 独立校验 Sub-Agent | 不参与原实现，审计各模块及集成 | 独立检查记录及针对缺陷的测试 | 缺陷复现、修复复验、通过/未通过判定 |

同一时间按可用并发槽位安排工作，完成一个开发包后轮换校验角色。依赖先由主 Agent 对齐，模块按边界并行修改；共享入口由主 Agent 统一接入。每次交接包含接口、实际命令、结果和已知限制，发现缺陷退回对应负责人修复。

## 首批集成边界

B0 建立独立的运行时技术验证入口，以用户提供材料检查工具循环和恢复。它只形成研究报告，不发布通用事件预测。模拟协议用于无 key 开发，界面或 API 明确标识 mock；真实 DeepSeek 验证另存调用及用量证据。

旧 API 和历史案例页面保留已验收的旧流程。B1 已将新事件投影器接入默认多任务工作台与人物，旧案例移至独立入口。未接入的前端模块不计为可见功能完成。

## 每批的验收顺序

1. 负责人完成模块，并给出可复现证据。
2. 主 Agent 接入完整路径，运行相关旧版回归与新增故障场景。
3. 独立校验 Agent 检查实现、验证权限与时间边界，报告问题。
4. 对应负责人修复，主 Agent 复验并更新实现状态。
5. 只有验收通过的条目记为完成；真实模型调用、离线协议测试、浏览器验收分别报告。
