# 简明流程展示附录

本附录用于组会及方案讲解，附在 PRD 0.2 阅读版的第 14–17 页，同时提供四页独立横版 PDF。它是下一版流程示意，实际实现状态仍以 PRD 和实现状态表为准。

## 1 从一个关注的问题到一份能验证的预测

讲解要点：先明确预测对象、期限和结果判定，再由主 Agent 安排调查。首版输出是与否概率，或者互斥候选的概率。结果附证据、分歧和更新时间，最后按既定规则核验。

图形约定：圆角框表示阶段起止，平行四边形表示输入输出，矩形表示执行动作，菱形表示条件判断，圆柱表示记忆存储。

## 2 先各自调查再围绕分歧补查

讲解要点：主 Agent 从十类研究员中按需选人。各自真实调用工具后共享报告，再判断是否需要且能够继续补查。达到预算或轮次上限时，可以记录资料不足或保留异议；不要求消除所有分歧才结束。

图中用官方、新闻、预测市场三类研究员举例。它们是十类角色中的示意组合，不要求每次启动全部角色。当前原型为五个固定角色，动态委派是下一版目标。

## 3 新消息怎样更新预测和记忆

讲解要点：先去重、查来源，再判断新消息是否影响预测。值得更新时，结合适用记忆开展新一轮调查，并发布新版本。旧预测和旧关系保留，真实结果出现后再结算、评分和修订经验。

图中的下轮取用表示读取适用经验，不代表保存图后立即无限启动会议。监听计划与消息触发规则共同控制下一轮，服务端在网页关闭后继续工作。时序图与通用监听属于下一版改造目标。

## 4 后端真执行像素人物才行动

讲解要点：执行事件先保存，再通过 SSE 推送。调查开始对应人物工作，报告提交对应本人气泡，会议消息对应实时发言，预测发布对应便签更新。

当前已有人物、SSE 和完成气泡。下一版补齐多任务隔离、事件协议和重连恢复。房间只跟随用户当前选择的运行，后台会议显示进度，不能抢占人物和发言。
