# 有界研究的网页工具取舍

2026-11-22。针对本轮 NVDA 调查中反复 `focus` 未命中、无关 BTC 报价和网页访问壳被当正文的问题。这里记录已检查的成熟资源和实际采用范围，不把候选组件写成已安装能力。

## 参考资源与本轮选择

| 官方项目 | 能力与适配条件 | 本轮取舍 |
| --- | --- | --- |
| [Mozilla Readability](https://github.com/mozilla/readability) | 从 HTML DOM 提取文章；Node 使用需要 DOM 实现（官方示例为 jsdom），并明确保持页面脚本执行关闭 | 当前 Fetch 已返回文本，Readability 不能直接修复后续精确定位失败。不额外安装 DOM／HTML 抽取栈 |
| [Trafilatura](https://github.com/adbar/trafilatura) | Python／命令行正文、元数据和结构抽取，支持表格等内容；当前版本采用 Apache-2.0 | 本项目运行路径为 Node，避免为已取得文本的定位问题引入 Python 服务；保留为自托管 HTML 抽取候选 |
| [Jina Reader](https://github.com/jina-ai/reader) | 将网页转换为模型易读内容，具有托管入口；官方说明匿名请求更易限流，部分功能需要凭据 | 不默认增加第三方转发、账户或浏览器依赖；未来若启用，需单独记录实际 reader、失败和授权边界 |

本轮没有复制这些项目的源码、安装其依赖或接入其托管服务。当前实现继续使用既有 DeepSeek Search／Fetch；改进发生在我们自己的有界取证与证据保存层。查询能力与网页正文抽取是两层，不能把新的文章解析器当成更完整的搜索引擎。

## 已实施

1. **原始正文按 URL 缓存。** `toolsFor` 接受内部 `cacheScope: runId`，同一 Run 的研究员可复用一次取得的正文；并发读取合并为一个请求。每个实际读者仍分别调用证据保存处理器并获得自己的读取记录，不把别人的引用 ID 直接移交。另一个 Run 重新读取。
2. **定位失败不丢弃已经取得的正文。** `focus` 只定位原文短词；精确匹配失败时返回 `partial`、`focusMatched=false`、真实连续降级片段和片段内的 `citationHints`。不会编造匹配段落。换行等价匹配只改变定位方式，不改变保存原文。
3. **访问壳不能成为证据。** 明确的“浏览器不支持”、验证／验证码等页面返回未取得可引用正文，提供替代公开来源建议；同 Run 重复换 focus 不再次抓取同一个壳。没有绕过登录、验证码或账户权限。
4. **报价按资产开放。** 未出现 BTC／ETH 的 NVDA、黄金等问题不再注册 Coinbase BTC／ETH 工具；出现单一支持资产时，模型看到的参数枚举只包含该资产。严格 BTC-USDT 工具仍按其固定政策独立开放。
5. **保存与权限规则保留。** 先检查公开 URL 和角色来源范围，再访问缓存；只有已实际保存的片段产生 evidenceId。原有报告出处、本人／本轮、时间及数值校验没有放松。

## 验证

`node --test server/course/web-tools.test.mjs`：25／25 通过。新增覆盖缺失 focus 降级、换行原文保真、跨读者共享但独立保存、跨 Run 重新读取、来源权限、访问壳拒绝、并发失败请求记账、单读者取消和错误资产不开放报价。

这些是本地协议／处理器回归，不是搜索质量基准或真实预测准确率测试。真实研究闭环由集成者另外运行并记录；本模块测试不调用付费模型。
