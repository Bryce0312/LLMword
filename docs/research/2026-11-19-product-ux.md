# 从材料工作台到低输入预测入口：产品与 UX 方案

日期：2026 年 11 月 19 日。状态：**只读审查后的设计建议，未实施**。依据为当前 M1 页面、PRD 0.3 与实现状态；本文不把自动搜索、多 Agent 调查、正式概率发布或概率时间图记为已有能力。

## 1. 本轮产品方向与范围

默认入口采用“预设模式”：用户写一句希望提前知道的问题，可选 24 小时、48 小时或 7 天，默认 48 小时。点击一次“开始跟踪”后，主 Agent 整理可验证问题、寻找来源并调查；系统理解卡随过程展示，用户可以纠错。已有明确日期的输入优先采用原日期，不能被默认窗口覆盖。

“严格模式”用于查看和修订预测契约，不要求用户学习 Agent、Tool、证据编号或模型配置。两种模式使用同一套时间、来源、权限和发布校验；预设模式减少人工填写，不降低结果标准。当前仍只设计 binary 是／否输出。

结果区先回答三个问题：**现在倾向发生还是不发生、发生概率是多少、为什么发生了变化**。时间图呈现同一问题的判断更新，不画成股价走势或未来概率外推。

### 课程演示版的边界

本轮所有技术服务课程作业，沿用现有像素场景，做出一条能讲清楚、能复现的路径即可。演示默认采用**主 Agent 加三名研究员**：原始出处、时间线与背景、反证与关系三个调查席位。职责名称可随已接工具调整；十类角色库保留在内部，普通用户不用配置，不新增选人平台或复杂管理流程。

课程结果页只保留四个主要区域：

| 区域 | 需要让组员和评委看懂什么 |
| --- | --- |
| 答案与概率 | 同一个二元问题、固定到期时间、当前倾向、已发布概率或暂未判断 |
| 变化曲线 | 概率如何随真实新证据更新；每个点可回到当时的判断和来源 |
| 谁查什么与气泡 | 主 Agent 怎样分工，三名研究员实际查了什么、哪里有分歧、何时提交 |
| 来源与关系 | 本题最关键的原文及其支持／反对关系，可用小图或清楚的对应表展示 |

桌面沿用中央像素研究室、右侧答案便签，下方放轨迹与来源关系。手机依次呈现答案、人物工作、轨迹、来源。新增账户、复杂工作区、更多题型、大型图编辑器和十角色配置流程不纳入本轮范围。

## 2. 当前界面的实际负担与能力边界

审查入口：[题目及材料表单](../../web/workbench-forms.js)、[研究室详情](../../web/workbench-detail.js)、[工作区导航](../../web/workbench.js)、[实现状态](../IMPLEMENTATION_STATUS.md)。

| 当前实际路径 | 用户需要处理什么 | 设计处理 |
| --- | --- | --- |
| 先创建主题 | 名称、背景、资料模式；没有主题无法建题 | 从问题生成主题，归档位置成为可改默认值 |
| 再创建预测题 | 主题、问题、对象、目标时间、停止发布时间、时区、规则、来源 URL | 默认自动整理，系统理解卡可见且可纠错 |
| 去收报台放材料 | 标题、正文、链接、关联题目 | 普通路径由系统实际检索并保存出处；用户材料是可选补充 |
| 回研究室开始研读 | 研究员选择、材料选择、每轮材料上限 | 系统按问题选择方法和资料，不作为用户必填项 |
| 查看报告 | 公开执行、引用和报告；概率为缺值 | 后续接正式发布后，才显示答案与概率轨迹 |

当前已经支持多题、不可变版本、角色定义、两种材料读取工具、持久事件和像素投影；**没有通用自动联网取证、正式概率发布、通用监听及概率更新曲线**。当前默认 official 研究员虽然无需用户修改，但显著的选择控件仍让人以为必须懂角色分工。

因此不能只隐藏材料表单、把按钮改叫“开始预测”。自动检索和有效发布必须有真实后端执行；尚未接通时，页面继续明确显示“材料研读版”，概率保持缺值。

## 3. 最少输入流程

### 3.1 预设模式：一句问题、可选窗口、一次开始

```text
世界事务所                         预设模式 | 严格模式

你想提前知道什么？
[ 甲公司这两天会正式发布产品 A 吗？                    ]
关注多久？      [24小时] [48小时 默认] [7天]
[开始跟踪]

主 Agent 自动核对对象、日期和可用来源，并继续调查
           ↓
系统理解：我们将跟踪……
正在调查                         [修改理解] [停止跟踪]
```

用户不用先创建主题。系统建议归入“甲公司产品动态”，可在纸签底部更改；不确定归属时暂存“我的关注”，不得为了分类阻塞调查。

时间按钮从服务端建立题目的时刻一次性计算：24 小时、48 小时或 168 小时，形成固定到期时间。纸签必须显示确切日期、时刻和时区；不能让“1 周”有时表示周日、有时表示七天。涉及交易日、当地营业日或原文明确日期时，保留对应口径；真正不清楚时纳入一次关键澄清。

输入含明确对象、事件和日期时，主 Agent 直接继续。只有实体或判定规则存在重大歧义时补一问，优先给短选项。仍无法判断时保留未执行草稿，说明需怎样改写，不继续展开问卷。用户问数值或名单时说明本期只支持是／否，可提供可编辑改写，不能擅改问题后开始调查。

开始后显示真实阶段：整理问题、寻找原始来源、独立调查、核对分歧、提交判断。来源暂不可用时显示实际失败与重试，不出现虚构搜索、伪造进度或默认 50%。普通用户可换问题或稍后重试；高级用户可以补资料，但不把手工填材料重新设为默认必经关卡。

### 3.2 严格模式：展开同一张纸签

展开可编辑问题定义、实体、窗口、停止发布条件、时区、结算规则、指定来源及来源更正／无法判定处理。默认值仍由系统填好，用户只改需要控制的部分；评估配置保留在开发侧。

严格模式仍由系统自动取证。现有角色与工具管理保留为开发者设置，预算由服务端限制，不占普通建题页面；本轮不扩建管理平台。调查开始时冻结实际配置，公开显示派工依据；当前 M1 仍须标一位研究员，主 Agent 加三研究员属于后续实现目标。

## 4. 规范化预览卡：开始后展示，可随时纠错

以下为**设计样例，非真实来源核验或预测数据**：

> **我们将跟踪**：甲公司是否在 2026 年 11 月 21 日 14:00 前，正式公告发布产品 A？
> **时间窗**：本题建立时刻起固定 48 小时，显示时区 Asia/Shanghai。
> **算发生**：指定官方来源明确产品 A 及正式发布事实；传闻、预告猜测不算。
> **如何判定**：优先核对公司官方公告及约定的补充来源；来源状态必须实际验证。
> **跟踪结束**：到达目标时间，或真实结果已由指定来源确认。
> **收进主题**：甲公司产品动态。
> **正在跟踪** / **修改系统理解** / **停止跟踪**

卡片最多先展示上述几行，完整结算细则可展开。问题对象、何时截止、什么算发生以及用什么判定必须可见；Agent 名单、工具参数、证据编号和模型原始消息不占主卡。

系统自动建议来源时区分“候选来源”“已成功读取”“覆盖不足”；只有 URL 不代表取得了正文。到期没看到公告也不能机械判 No：须满足约定来源覆盖和结果规则；取证失败、结果迟到或来源矛盾保持待核验。

自动建立题目时固定版本、目标时间和结算规则。用户纠错涉及实质定义时，停止旧口径的新发布，再建立新版本；旧报告与轨迹保留。到期后“继续关注”创建新题及新目标，不能把“未来 48 小时”每天自动顺延，也不能把滚动 48 小时的不同事件口径拼在同一条曲线上。

默认停止发布时间可以等于目标时刻，但指定结果先公开时提前关闭有效发布；执行器仍按实际提交时间检查。截止前开始、截止后完成的调查只保存研究报告，不进入有效预测轨迹。

## 5. 结果页：答案、概率、变化原因

结果便签的主次顺序：

1. 完整规范化问题与目标时间；不能只写“甲公司预测”。
2. 当前公开答案，例如“倾向发生”；同时写“发生概率 62%”，明确这是模型估计。示例数字不进入真实任务。
3. 发布时刻、证据截止、最近一次有效更新、当前契约版本；资料充分程度另列，不能称为“概率置信度”。
4. 一至两句公开变化原因与可点击原文，例如“新增正式公告，较上次上调 8 个百分点”。有变化才显示差值。
5. 判断更新轨迹、下一次检查安排与停止跟踪入口。

尚未有有效发布时显示“正在调查，尚无可发布概率”；资料不足显示“暂未判断”、缺口与下一步。这是工作状态，不是第三种事件结果，不参与 Yes／No 概率归一化。概率约等于 50% 时可说“两种结果接近”，但 50% 不能作为默认填充值。实际结算结果使用独立标记，不把结果确认硬添成最后一个 100% 或 0% 的预测点。

## 6. 概率时间图：历史更新不等于未来走势

### 6.1 默认图的含义

图名为“**判断更新轨迹**”，横轴是实际发布时间，纵轴固定为“该事件在约定期限内发生的概率（0–100%）”。一条线仅对应同一个 predictionId、契约版本及固定目标时间；runId 可以变化，但不能混入旧契约。

绘制真实发布点及阶梯线，水平段表示沿用上次已发布判断，不代表每个时刻重新计算。线只到最后一个真实发布点，**不向未来延伸，也不从最后一点拉到‘现在’冒充新更新**。当前时刻单独画竖线；从现在到目标日期的未来部分保持空白或淡斜纹，标“尚未发生的跟踪时间”。初期仅一个点就显示一个点，不补出漂亮曲线。

点击或键盘选择某点，显示发布时间、概率、目标时间、使用的具体证据版本、变化原因和研读记录。原文发布时间不能替代预测发布时间，不能把今天取得的旧报道回填成几天前已有的概率。

### 6.2 必须避免的误读

| 情况 | 应怎样显示 |
| --- | --- |
| 定时检查成功，但没有新判断 | 更新时间状态，不增加概率点 |
| 重复转载、重复会议、SSE 重投 | 不制造额外变化点；按 forecastId 去重 |
| 取证中断或旧判断过期 | 标注空档／陈旧状态，不用平滑线假装持续观测 |
| 新证据使概率从 54% 到 62% | 显示上调 8 个百分点及依据，不称“未来会上涨 8%” |
| 用户把截止时间从两天改成一周 | 新契约独立轨迹，旧线仅在历史视图查看 |
| 到期发生或未发生 | 在结算栏显示结果和误差，预测线停止 |
| 模拟示例或历史重建 | 独立标识与视图，不混入真实前瞻轨迹 |

如果用户真正想问“未来每天的发生概率”，那是多个未来期限的预测，不是这张历史更新图。以后若做，必须单独定义各期限或情景、显示生成时刻与假设，并与真实更新轨迹分开；本期不先画一段虚线当作已经具备的世界模拟结果。

曲线所需的不可变发布记录至少包含 forecastId、predictionId、predictionVersion、publishedAt、evidenceCutoff、输入清单、probabilityYes、公开理由与有效性状态。M1 的运行报告不能直接转换成这些点；正式发布接口和校验尚需开发。

## 7. 像素风继续承担工作，而非装饰

保留现有深梅木框 #503746、墨色 #282637、羊皮纸 #f7e6ba、琥珀 #efb85f 和灰绿 #78a99d，沿用 Lab Pixel 字体与清楚的中文层级。全界面保持像素场景和硬边构件，不改为证券终端或通用圆角卡片仪表盘。

公告栏仍是多任务入口；中心研究室保留真实工作的研究员；右侧纸签优先显示用户问题与答案。新建入口从八字段表单缩成一张委托纸签，严格规则折叠在纸签内。把“问题纸签＋真实人物工作”作为主要视觉记忆点，其余信息安静、左对齐并按需展开，不增加无用途的装饰仪表。

收报台接收系统实际取得的原文，黑板展示已验证关系及反例，档案柜只收结算反馈，席位管理进入研究室设置；各物件继续保留独立目的地及等价文字导航。自动派工也必须由后端事件驱动动作和本人气泡，后台任务不抢当前房间。前端只展示公开计划、工具、证据和判断摘要，不展示模型隐藏思维链。

手机先呈现问题和当前答案，再显示研究室与轨迹；图在必要时横向查看，页面本身不溢出。提供可读的更新时间列表作为图的等价入口，支持键盘、读屏及减少动态效果。气泡正文内部滚动，标题不能被场景裁切。

## 8. 建议开发顺序与验收

本轮交付研究梳理，后续按下列依赖继续实施；表中内容均是设计目标。

| 顺序 | 需要完成什么 | 防止过度承诺 |
| --- | --- | --- |
| A：低输入契约 | 预设／严格模式、一次开始、自然语言规范化、可纠错理解卡、主题自动归档 | 未有自动取证时仍标研读，不启用假预测按钮 |
| B：真实调查入口 | 实际搜索及原文处理器、来源状态、按题派工、证据冻结和失败路径 | 角色方法存在不代表专用外部工具已接通 |
| C：正式预测闭环 | 有效概率发布、不可变版本、真实监听更新、结果核验与评分 | M1 报告和缺值不能冒充有效发布 |
| D：轨迹与可用性 | 真实发布点、状态空档、历史版本、移动端和可访问性 | 不能以视觉曲线代替发布账本和评估证据 |

建议验收：

- 普通用户用一句问题和默认窗口，点击一次开始即可继续调查；不必创建主题、选人、填材料或重复确认。
- 明确日期不被默认值覆盖；1／2／7 天的确切截止与时区可见；含糊问题只补关键缺口。
- 两种模式生成同样可验证的契约；真实结果已知后不能发布计分预测。
- 自动来源查询失败显示失败，不伪造正文、进度或 50% 概率；权限与预算仍由后端执行。
- 结果明确区分模型判断、资料充分程度、实际结算；未发布仍是缺值。
- 一个发布记录对应一个轨迹点；重复投递不加点，无新证据不刷曲线，未来区域无外推线。
- 改题后不混用旧报告和旧曲线；回放、重建和真实前瞻状态明确分开。
- 每个点能回到当时实际可见的来源；来源迟到、无法判定和更正有独立状态。
- 桌面及 390px 可用，键盘／文字列表能读取全部时间点；真实动作与完成气泡不被简化流程削弱。

### 可配置的设计起点

| 项目 | 本轮起点 |
| --- | --- |
| 时间窗 | 默认固定 48 小时，可选 24 小时／7 天；到期续跟踪建新题 |
| 首轮团队 | 主 Agent 加三名研究员；无需用户配置十类角色库 |
| 来源 | 官方原始来源与新闻；Polymarket 仅在合约事件、期限和结算口径对齐后作为参考 |
| 检查节奏 | 开始时取证一次；建议官方来源每 4 小时、新闻每 1 小时检查，按来源允许频率调整 |
| 概率更新 | 取得有意义的新证据后研判；定时检查本身不自动增加曲线点 |
| 预算 | 服务端限制调用、token、并发、时限及重试，用户不用填技术参数 |

这些是可配置默认值，实际启用须由真实连接器、调度及发布记录支撑。课程演示重点是四个结果区和一条真实协作闭环；未接通的能力保持明确状态，不用更多管理功能替代。
